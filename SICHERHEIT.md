# Sicherheit: Gefahren und Gegenmaßnahmen
Stand: 2026-11-18

Was im Paket schiefgehen kann, wer es auslöst und was dagegen steht. Erzwungen heißt: **Code** prüft der Server oder das Skript selbst, **Skill** steht nur in Skill, Hausregeln oder Anleitung des Servers und hängt davon ab, dass Claude sich daran hält, **beides** heißt, der Code begrenzt die Folgen und der Skill den Rest. Jedes Werkzeug der Stufe nachfrage aus `apple` und `chat` steht hier, `paket.py --pruefen` meldet sonst einen FEHLER.

Gemeinsamer Unterbau aller Zeilen mit Dialog: Vor jedem Werkzeug der Stufe nachfrage zeigt `mcp_basis.Server.ausfuehren` einen Dialog von macOS (`mcp_basis.bestaetigen`). Vorauswahl ist Abbrechen, ohne Klick nach 120 Sekunden oder ohne möglichen Dialog gilt er als abgelehnt. Claude sieht den Dialog nicht und kann ihn nicht freigeben. Im Modus lesen (`KITS_NUR_LESEN` oder `mcp_nur_lesen` in der `config.json`) bietet der Server nur Werkzeuge der Stufe lesen an (`server.py`, Funktion `server`). Löschen gibt es in keinem Server.

## Nur im Skill

Diese Gefahren hält heute nur die Regel im Skill auf:

- **Antwort auf die falsche Mail:** Etappe 2 von v7.3.0 prüft den Betreff im Code (`betreff_erwartet`).
- **Überschreiben von Notizen mit Anhängen, Zeichnungen oder Checklisten:** `notiz_ersetzen` erkennt sie nicht.
- **Persönliche Daten aus Kontakten in Dateien oder Memory:** kein Werkzeug kann das Ablegen verhindern.
- **Rückfragen in Home Assistant** (Schlösser, Löschen, Neustart) im Server `homeassistant`: nur Hausregeln, der Lese-Server sperrt im Code.
- **Prompt-Injection allgemein:** Der Hinweis in den Ausgaben ist Text. Der Code begrenzt nur die Folgen über Dialoge, fehlende Sendewege und erlaubte Ordner.

## Pflege

Neues Werkzeug der Stufe nachfrage: eine Zeile hier ergänzen, sonst meldet `paket.py --pruefen` einen FEHLER. Neue Gefahr oder neuer Schutz im Code: Zeile anpassen und `Stand` auf heute setzen.
